# 测试模型

测试层按要回答的问题划分，Playwright、React Testing Library、HTTP 客户端等只是执行工具。

没有独立的 E2E 层。跨页面或跨领域的端到端用户流程属于 Journey；“端到端”可以描述覆盖范围，不作为另一套层名或目录。

| 测试类型 | 子类 | 回答的问题 |
|---|---|---|
| Unit | — | 单模块规则是否正确 |
| Functional | Backend | 后端单一入口或单一能力是否可用 |
| Functional | Component | 前端单组件是否正确渲染并响应交互 |
| Integration | — | 少量模块协作后，业务结果、数据写入或外部调用是否正确 |
| Integration | Journey | 跨领域、多步骤后，用户看到的结果和持久化状态是否正确 |

仓库已有层名和目录优先。没有项目规则时，测试可分别放在 `tests/unit/`、`tests/integration/`、`tests/functional/`、`tests/performance/`，共享数据放在 `tests/fixtures/`。

选择测试层时问：用 Mock 替代下游依赖之后，当前风险还能出现吗？能则使用更小的层；不能则保留真实协作。同一风险只在最合适的测试层验证一次。

## 行为与状态

- 通过公共接口验证用户可观察行为，不依赖私有函数、内部调用次数或样式类名。
- 每个用例只回答一个问题；Journey 可以包含多步，但只描述一个用户故事。
- 写入、更新、删除和迁移除了响应外，还要验证可再次读取的持久化终态；纯计算只验证结果。
- 正常、失败和边界场景按风险选择，不机械遍历与业务无关的所有类型组合。
- 测试数据保持最小、可重复、与生产数据隔离。时间、随机数和标识符在需要确定性时固定。

## Mock

只 Mock 测试目标之外、无法控制或代价过高的外部依赖，例如外部 HTTP、LLM、worker。不要 Mock 当前测试要验证的内部协作，也不要为了方便 Mock 而在业务代码中增加公共接口、适配器或依赖注入层。

真实调用是否必要取决于风险：

- 测试状态流转、持久化结果和错误转换时，可以用固定返回值替代昂贵依赖。
- 提示词（Prompt）、生成质量或自愈能力需要真实模型；缺少凭证时只跳过对应测试。

## Web

优先使用用户可感知的语义角色和名称。无法稳定定位时再使用项目约定的测试属性，最后才使用 CSS 类名或 XPath。等待可观察条件，不使用固定时长等待。

## 迁移测试

迁移测试至少证明：

- 每个相邻版本能从 N 升到 N+1。
- 失败时版本号不前进，旧数据仍可恢复。
- 少量长链路冒烟测试能从支持的最早版本升级到最新版本。
- 测试数据库和文件与生产数据隔离。

## 准备、执行、断言（AAA）

测试使用 Arrange、Act、Assert 组织准备、行为和可观察结果。预期值应直接写明或来自需求和固定样例，不能在测试中重新执行生产算法来计算。
