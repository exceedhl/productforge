# LLM 回复用语约定（通用）

适用于 **所有** `/pf` 子命令产出与对话回复。
**不是** `/pf review` 的 Conventions 轴标准；Conventions 轴只评代码命名、目录、日志、迁移（见 [conventions.md](conventions.md)）。

本文件是唯一维护入口。仓库 `AGENTS.md` 可以要求每个会话首次回复前读取本文件，但不复制正文。

---

## 1. 一律用本义与标准术语

判定标准只有一条：**把这句话给没读过这段代码的人，他能不能懂**。懂不了就改写成本义。

- **协议、接口、凭证、错误用官方名**：`access_token`、`refresh_token`、授权码 `code`、刷新、single-use、refresh token rotation。
- **没有通行中文译名时保留英文**（idempotent、backpressure），或用「幂等」「背压」这类已通行的译名，不另造中文说法。
- **比喻和口语改写成动作本身**：说清谁、对谁、做了什么。

## 2. 术语替换表

左列是最常犯的几个，按右列写。表格是第 1 节判定标准的例子，不是穷举：任何需要读者先懂代码才能解码的词，都按同样方式换成本义。

| 不要写 | 改写成 |
|---|---|
| 打 API、打接口、打 token 接口、打飞书 | 访问 / 请求 / 调用某个接口，如「请求飞书的 token 接口」 |
| 票、换票、兑票、一次性票据 | 凭证的官方名：授权码 `code`、`access_token`、`refresh_token`、刷新、single-use |
| 表不发网 | 「表格组件自己不请求 HTTP API，由所在页面传回调进去请求」 |
| 打一枪、点一下试试 | 「触发一次请求」「手动执行一次刷新」 |
| 钉住（版本、返回值、断言） | 固定版本 / 用固定返回值 mock / 断言等于某个具体值 |
| 一刀（一刀改完、一刀切） | 一次改动 / 一个提交 / 统一按同一规则处理 |
| 落点、落在哪 | 写入路径 / 存放目录 / 文件写入位置 |
| 出站、出网 | 对外请求 / 访问外部服务 |
| unwrap（混在中文句子里） | 取出 `data` 字段 / 从 Result 中取值 |
| 契约适配层、胶水层 | 直接写职责：「把后端响应字段映射成前端类型的转换函数」 |
| 兜底（不说兜什么） | 说清降级行为：「请求失败时改用本地缓存并提示用户重试」 |
| 欠债、收口、边界成立 | 说清事实：缺了什么、谁在何时补、职责归到哪一处 |
| SPI、inbound / outbound、fire-and-forget、jobType 等内部缩写 | 第一次出现先给本义（「入站指从飞书读进来」「发起后不等结果返回」），之后才可以用缩写 |
| 世代 | 版本 |
| 现网 | 当前实现，当前状态 |

## 3. 引用必须可定位

凡引用代码、文档、日志、官方说明，都要给出读者能立刻点开或搜到的位置：

- **对话里引用代码**：用代码引用块，首行写 `起始行:结束行:文件相对路径`。这是对话里唯一能点开并跳到那几行的形式，正文里裸写 `path/file.ts:53` 点不开。
- **写入 Markdown 文件时引用代码**：链接目标只放**单行**锚点，行区间写在链接文字里，例如 ``[`backend/modules/datasets/datasetPublishService.ts:53-79`](../../backend/modules/datasets/datasetPublishService.ts#L53)``。**不要写 `#L53-L79`**：区间锚点在 Markdown 预览里不跳行，只会打开文件顶部或直接报找不到文件。
- **仓库文档**：相对路径，必要时补标题或节名。
- **外部资料**：完整 URL。

禁止无出处摘句，禁止只写「见上文」「如前所说」而不指回具体位置。

## 4. 回复的组织方式

- **结论先行**：第一句回答「发生了什么」或「结论是什么」，理由、过程、限制条件依次排在后面。评审报告的问题项正文例外，那里按调用顺序讲机制（见 [review.md](review.md)）。
- **完整句子写因果**：术语写全称，不用 `A → B → 失败` 这类压缩链，不用电报体短语堆叠。
- **已验证与推测分开**：跑过命令、读过文件得到的结论直接陈述；没验证的明确写「未验证」，并说清缺哪一步验证。
- **中文正文，标识保留英文**：正文用中文和全角标点；文件名、ID、代码标识、路径保留英文并用反引号包起来；中文句子里的英文和数字两侧留空格。
- **信息不够先问**：缺关键输入时先提一个具体问题，不要用空泛分析或泛泛结论填满篇幅。
- **篇幅按任务复杂度成比例**：简单问题直接一句话答完，不加标题分节；机制解释和评审问题项要写透，不压缩成 2–4 句结论。
- **表格只用于结构化产物**：Backlog、画像、Decision Board、六轴清单这类可枚举事实用表格；对话里的解释性内容用段落，不要把说明塞进单元格。
